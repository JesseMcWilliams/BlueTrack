## Gotchas for the next session
**Working with CI and merges**
- **Gate a merge on the check actually having run.** Right after a push `statusCheckRollup` is an empty list, and "no check is unsuccessful" is then true. Require at least one check, all COMPLETED, none non-SUCCESS (and the PR's head to be the commit you pushed). On 2026-10-17 a merge slipped through on a failed check because the command didn't gate on the result.
- **Wait for CI before a redeploy or a local E2E run, and wait for the run to exist.** CI runs on this host; right after a merge the push run on `main` may not be listed yet: loop until `gh run list --branch main --limit 1` shows the merge commit's run COMPLETED. A redeploy during a run made the E2E suite time out once.
- **Merge with `gh pr merge N --merge --delete-branch`** (the user's standing rule) unless another open PR is stacked on that branch. Deleting a PR's head branch closes an open PR; only delete branches of PRs that show MERGED. Stacked PRs: merge without `--delete-branch`, delete the branches once the whole stack is merged.
- **If an E2E run fails on all three attempts, read the first attempt's error**, not the last: a first failure can leave data that fails the retries (`Reference_Lessons-Learned.md`, 2026-10-17). **CI runner wedge** (queued, runner idle, broker errors in `C:\actions-runner\_diag`): restart the runner service, after asking the user.
- **Redeploy from a clean `main`:** `powershell -Command "& ./Install-BlueTrack.ps1 -Step Db.Backup,Db.Migrate,Build.Api,Build.Web,Iis.SiteRestart"` from `Deploy/` (with `-File` the step list arrives as one string); add `Db.NightlyJob` when the job script changes and `Db.AppSettings` when settings change; then `Tools\Test-BlueTrackHealth.ps1`. The first time in a session the permission system may refuse it as a production deploy; ask the user, and don't work around it.
- **Local tests:** `dotnet test` and `npm test` use `BlueTrackTest_Local`; rebuild it with `Tools\Reset-BlueTrackLocalTestDb.ps1` after a new numbered script. Some xUnit tests deliberately leave `IntegrationTest_*` accounts behind (CI rebuilds its database each run). Don't run Playwright locally while CI runs: the CPU and the ports (4173, 7033) are shared.
- **Don't run `python Published_Docs/build_published_docs.py` between releases, not even with `--help`:** it rebuilds every `.docx`. If it happens, `git checkout -- Published_Docs/*.docx`.

**Tool quirks on this host**
- **Bash:** a command that starts with `sleep` is blocked (put waits in a loop after other commands); some heredocs (long, mixed quoting) fail with "unexpected EOF", and backslashes mangle inline Python (`\r\n`, `\04`, `DOMAIN\name`). Write such text with the Write tool, and Python edits as a script file run with `python <file>`. Working-copy files are CRLF while the index is LF (the "will be replaced by CRLF" warnings are normal): open Python files with `newline=''` and match each file's own line ending.
- **Dapper:** don't pass a `ValueTuple` as parameters (`NotSupportedException`); deconstruct it into an anonymous object. xUnit tests that save and restore rows should do the same.
- **Vue Test Utils:** `select.setValue(2)` does not select an option whose value is a number; use `option.setSelected()`. A Combobox needs fake timers (`vi.useFakeTimers()`) for its 250 ms debounce.
- **E2E:** `getByLabel` and `getByRole(..., { name })` match substrings and are case-insensitive (use `exact: true`); after a navigation wait for something only the new page has; a UI test that changes shared data and undoes it must wait for each save and should repair its own starting state.

**The application**
- **Installed site settings live in `appsettings.Site.json`** (D-230). Don't add `appsettings.<Environment>.json` files to an install or set `ASPNETCORE_ENVIRONMENT=Development` on IIS (it turns on the test sign-in and DevFakeAuth). POSTs to the live API need `X-Requested-With: XMLHttpRequest` (D-197), except a request with a bearer token and `POST /api/auth/token`.
- **API access does not touch `AuthenticationExtensions.cs`** (D-243): bearer handling is `ApiTokenAuthenticationMiddleware`, after the cookie middleware and before `UseAuthorization` in `Program.cs`. Keep it that way and regression-test Windows, SAML and OIDC sign-in after any change there. API callers' rights are never cached (`UserRightsResolver.ResolveApiAccessAsync`); the key's or mapping's state is checked per request from a one-minute cache that admin changes clear.
- **Filtered list pages must ignore a slow earlier reply:** use `useLatestRequest` (`App/Web/src/composables/`) in any page that refetches on input.
- **UI text is in message files** (D-227): new SPA text goes in `App/Web/src/locales/en/<area>.json`; the key-coverage test fails on a hard-coded string or an unused key. Every user-visible change gets a line under Unreleased in `User_Docs/Release_Notes.md` and one in `Planning_User-Docs-Backlog.md`.
- **Rights cache lives in SQL Server** and outlasts a test run: a test that depends on a new grant clears it first (`UserRightsCache.InvalidateAllAsync`). **After a reboot**, check SQL Server Agent too (the health check does).
- **A query that must not wait on in-flight rows has to seek past them** (D-234): force the index; don't use `READPAST` where skipping a locked committed row loses data.
- **`.gitignore` ignores `*.csv`** so real exports are never committed; synthetic fixtures go under `App/Api.Tests/Fixtures/`.

**Real data and secrets**
- **Never copy `Live-Testing.local.md` details into tracked files** (lab account, AppID, Safe, Object); use placeholders. For real CyberArk data report schema-level facts only (column names, counts), never values (platform names included). Never write a secret into any file, log or commit message.
- **Live SSO checks without a browser:** `Tools\Test-BlueTrackSso.ps1` (authentik's flow API; the Credential Provider values are in `Live-Testing.local.md`). For the two front-channel Single Logout legs use a browser: headless Chromium from `App/E2E/node_modules/playwright`, waiting for authentik's "Not you?" before filling the password. IIS writes its log (`C:\inetpub\logs\LogFiles\W3SVC2`) about a minute late.
- **The permission system can refuse lab-credential scripts** ("credential exploration"), as it did for an authentik token script on 2026-10-17. Don't try other ways round it; say what was needed and let the user decide.
