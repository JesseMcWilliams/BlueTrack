# Web Interface Design Document — Design Decision Register

**Blueprint Progress Tracking Web Interface**

## Purpose

A single running record of what's been decided about the web interface design, and what's still outstanding, so decisions made in one conversation don't get lost or quietly re-litigated later. Each of the companion design documents (Authentication, Authorization, Secrets Storage, Risk Exception Tracking, Interface Extensibility, Audit Logging, Application Structure, Data & Editing Behavior, Testing Strategy, Accessibility & Theming, Admin Deployment Management, Risk Scoring, Notifications, Credentials Management) has been updated to reflect the resolved decisions below — this register is the index of all of it in one place, plus everything that hasn't been designed yet at all.

| D-01 | Authentication | Should a break-glass path exist if all configured providers fail? | Approved — a break-glass path will be included. |
